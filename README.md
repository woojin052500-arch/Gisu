# Gisu (다음기수)

기수제 유료 프로그램 운영자를 위한 도구. 스터디·챌린지·부트캠프처럼 **같은 프로그램을 기수마다 반복해서 여는 사람**이 대상이다.

신청 폼 만들고, 입금자명 대조하고, 명단 옮겨 적는 일을 링크 하나로 끝내는 것이 목표.

---

## 현재 단계

수요 검증 중. 제품은 아직 없고, 랜딩으로 사전 등록을 받으면서 실제 운영자를 만나는 단계다.

서버가 없다. 정적 파일 + Google Apps Script로만 돌아간다.

---

## 구성

```
index.html            랜딩 페이지 — 사전 등록(전화번호) 수집
apply.html            신청 폼 — 운영자에게 직접 쥐여줄 도구
apps-script/Code.gs   신청·사전등록을 구글 시트에 저장하는 백엔드
docs/실행가이드.md     배포와 운영 절차
docs/*.docx           사업성 검토 보고서 (시장 조사, 유닛 이코노믹스)
```

### index.html

랜딩 페이지. 방문한 운영자에게 제품을 설명하고 전화번호를 받는다.

- 사전 등록은 히어로(번호만)와 하단(이름·번호·프로그램 종류) 두 곳에서 받는다
- 등록자 수는 10명을 넘겨야 "이미 N명이 등록했습니다"로 노출된다. 숫자가 적을 때 보여주면 등록을 막는다
- 주소 끝에 `#stats`를 붙이면 운영자용 등록 현황이 보인다 (`index.html#stats`)

### apply.html

실제 신청을 받는 도구. 사전 등록한 운영자를 만났을 때 바로 쓰게 해주는 용도.

- 운영자가 프로그램 정보를 채우면 링크가 나온다. 정보는 URL 해시(`#d=`)에 인코딩되므로 서버가 필요 없다
- 신청자는 회원가입·앱 설치 없이 링크만 열면 된다
- 접수 완료 화면에서 **입금자명을 신청자 이름으로 맞추도록 안내**한다. 대조 사고의 대부분이 여기서 사라진다
- 신청자 수·남은 자리·미입금 인원을 운영자 화면에서 조회한다

---

## 배포

정적 파일이라 아무 데나 올리면 된다.

**GitHub Pages** — Settings → Pages → Source를 `main` 브랜치 루트로 지정.
`index.html`이 루트에 있으므로 저장소 주소가 곧 랜딩이 된다.

**Netlify Drop** — https://app.netlify.com/drop 에 폴더째 끌어다 놓으면 즉시 주소가 나온다.

### 백엔드 (최초 1회)

1. 구글 스프레드시트 생성 → 확장 프로그램 → Apps Script
2. `apps-script/Code.gs` 내용을 붙여넣고 저장
3. 배포 → 새 배포 → 웹 앱
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**  ← 아니면 데이터가 들어오지 않는다
4. `/exec`로 끝나는 URL을 `index.html`의 `WEBHOOK`, `apply.html`의 `DEFAULT_WEBHOOK`에 넣는다

> Code.gs를 수정하면 저장만으로는 반영되지 않는다. **매번 새 배포**를 해야 한다.

시트는 두 개가 자동 생성된다.

| 시트 | 내용 |
|---|---|
| `사전등록` | 랜딩 사전 등록자. 같은 번호는 중복 저장되지 않는다 |
| `신청자` | 프로그램 신청자. `입금확인` 열은 손으로 채운다 |

---

## 알아둘 것

- **웹훅 URL은 공개된다.** 클라이언트에서 호출하므로 브라우저 개발자 도구에서 누구나 볼 수 있다. 저장소를 비공개로 돌려도 마찬가지다. 스팸이 들어오기 시작하면 Code.gs에 간단한 검증(허니팟 필드, 제출 간격 제한)을 넣는다
- **개인정보를 다룬다.** 전화번호를 수집하므로 수집 목적 외 사용 금지, 요청 시 삭제, 시트 공유 범위 최소화를 지킨다. 랜딩과 신청 폼 모두 동의 문구가 들어가 있다
- **apply.html의 링크가 길다.** 프로그램 정보를 통째로 담고 있어서다. 서버를 붙이면 짧아진다
